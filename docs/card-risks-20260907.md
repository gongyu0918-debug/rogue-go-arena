# 卡牌风险记录（2026-09-07）

按本轮范围，卡牌只检查、记录风险，机制与数值留到下一轮。本轮没有修改卡牌目录、概率、次数、奖励或触发条件。

核对范围为 `app/data/cards.json` 的 37 张普通卡、25 张终极卡及对应玩法代码。下表区分已核实的规则与待试玩验证的体验风险；没有玩家选取率、使用率或满意度数据，不将设计判断写成实测结论。

| 编号 | 位置 / 当前规则 | 风险与依据 | 下一轮验证重点 |
| --- | --- | --- | --- |
| C-01 | `rogue/dice`：AI 每手 6% 概率虚手 | 选卡后没有主动操作，可能连续多手无反馈；无聊程度尚未量化 | 首次触发手数、整局未触发比例、玩家能否影响触发时机 |
| C-02 | `rogue/nerf`、`time_press`、`suboptimal`：分别削弱搜索、限制时间、从较差候选点中选着 | 三张卡体验可能重叠，容易把有意的棋力干扰与引擎错误混淆 | 用相同局面比较可辨识度、实际收益和重复选取意愿；合法性与劫禁必须独立保留 |
| C-03 | `rogue/komi_relief`：名称为“贴目减半”，实际向玩家有利方向调整 7 目 | 名称与实际规则不符是已核实问题；开局一次生效也可能缺乏后续参与感 | 统一各语言名称与规则的对应关系，再评估被动收益卡的定位 |
| C-04 | `rogue/mirror`、`slip`、`shadow`：分别以 16%、12%、18% 概率改变 AI 落点 | 用户难以主动利用概率窗口；发生时可能被理解为 AI 乱下 | 触发原因、原目标和实际目标的可理解性；确认合法性过滤与卡牌禁区都被保留 |
| C-05 | `rogue/seal`、`blackhole`、`golden_corner`：全局或长期禁入指定区域 | 一次选定后后续决策有限；禁区可能压缩合法落点和劫材 | 封锁叠加、无合法候选、双方持卡及打劫边界；体验问题待人工试玩 |
| C-06 | `rogue/god_hand`：隐藏区域触发 | 未触发时可能缺少可解释反馈；是否造成大量空耗局待验证 | 不同棋盘阶段的触发率、玩家对隐藏范围的理解与反馈需求 |
| C-07 | 终极卡中的大规模随机增殖、清除、转色与连锁 | 爆发规模大但不同卡的操作感可能趋同；连锁还可能放大结算和视觉开销 | 机制辨识度、链式触发上限、结算耗时与有效选择次数 |

下一轮可复用 `tools/card_balance_eval.py` 和现有卡牌配置/效果 smoke，补充人工试玩。仅凭胜率变化不能证明卡牌更有趣。参考开发者关于[卡牌定位与平衡](https://www.gdcvault.com/play/1025731/-Slay-the-Spire-Metrics%EF%BB%BF)及[随机性设计](https://www.gdcvault.com/play/1028984/Cards-Dice-and-RNGs-Using)的讨论；本表具体风险来自本项目核查，不是外部资料对这些卡牌的评价。

## HTML 兼容核对补记（2026-09-08）

HTML 旧版有 34 张普通卡，WebView 有 37 张；天元连下、低线、额外棋子、增殖、五子连珠与提子犯规等规则已分化。直接整合桌面核心会改变 HTML 玩法，所以本轮只移植通用修复。下一轮需要先决定两分支是否统一规则，再评估卡牌改造。

桌面版配置覆盖与说明也存在偏差：`fog` 代码默认半径 1、说明为 3×3，但 `cards.json` 配置半径 2，实际覆盖 5×5；`quickthink` 说明与默认时间为 2+1 秒，配置为 1+1 秒。本轮仅记录，没有修改配置或文案。需要以最终载入的配置作为下一轮校验基准。
